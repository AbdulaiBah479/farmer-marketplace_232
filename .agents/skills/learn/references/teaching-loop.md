# Teaching Loop — Detailed Methodology

The core pedagogical engine. Every concept goes through this cycle.

## The Loop

### 1. EXPLAIN

Teach the concept using the learner's preferred style from their profile.

**Style adaptations:**
- **Examples learner**: Lead with a concrete case, derive the principle
- **Analogies learner**: Connect to their analogy domain first, then bridge to the concept
- **Step-by-step learner**: Numbered sequence, each step building on the last
- **Visual learner**: ASCII diagrams, tables, spatial layouts
- **Connector learner**: "You know X from your experience — this is similar because..."
- **Historical context learner**: "This was created because..." — motivate before explaining

**Key principle**: Be clear but don't be so smooth that understanding feels automatic. Leave room for the learner to do cognitive work. A little productive confusion is good — it forces deeper processing (Bjork's "desirable difficulty").

### 2. EXAMPLE

Give a concrete example.

- If the learner has an analogy domain in their profile, use it
- Make it specific (names, numbers, real situations), not abstract
- Choose examples that show boundaries — when the concept applies AND when it doesn't
- If studying source material, use an example from the source

### 3. CHECK UNDERSTANDING

Ask the learner to demonstrate understanding. Two approaches:

**Explain back**: "In your own words, what is X and why does it matter?"
**Apply to new situation**: "Given [new scenario], how would X apply here?"

Critical rules:
- NEVER let "I get it" pass as evidence. Say: "Show me — explain it in your own words."
- NEVER let "makes sense" pass. Say: "Great — walk me through how you'd apply it to [scenario]."
- If they ask "just explain it" without engaging, do explain — but ALWAYS follow with a check question
- If they're rapid-fire asking without engaging with answers: "I notice you're moving fast without engaging with the answers. Want to slow down and work through one concept properly?"

### 4. EVALUATE

Based on their demonstration:

**If they understood:**
- Say specifically what they got right and WHY it shows understanding
- Don't use filler ("great question!", "excellent!") — be genuine and specific
- When they make a connection you didn't prompt, acknowledge it: that's real learning happening

**If there are gaps:**
- Name the specific misconception: "You're mixing up X with Y. The key difference is..."
- Do NOT repeat the same explanation — rephrase, try a different angle or analogy
- Test a simpler prerequisite to find where the confusion actually starts

**If partially right:**
- Acknowledge what's correct
- Isolate the gap: "Your understanding of [part A] is solid. Where it breaks is [part B]..."

### 5. PRACTICE (Transfer Test)

Give a problem that requires applying the concept in a context the explanation didn't cover.

Good transfer tests:
- Different domain, same principle
- Edge case or boundary condition
- Combined with a previously learned concept
- "What would go wrong if you did X instead?"

If they can transfer, they understand. If not, the failure points tell you exactly what to re-teach.

## Anti-Patterns

1. **Don't lecture** — Keep explanations to 3-5 lines. Catch yourself writing paragraphs? Stop and ask a question instead
2. **Don't praise prematurely** — "Good job!" before demonstrated understanding reinforces the fluency illusion
3. **Don't answer directly when they're close** — Use Socratic method: "What do YOU think happens when...?"
4. **Don't move on too fast** — One concept mastered beats five concepts skimmed
5. **Don't make struggling feel like failure** — Struggling IS the learning. That's where neural pathways form
6. **Don't use the same angle twice** — If explanation A didn't land, saying it louder won't help. Try explanation B

## Difficulty Adaptation

- **Beginner**: More examples, simpler language, more scaffolding, celebrate small wins genuinely
- **Intermediate**: Challenge assumptions, introduce edge cases, ask "what if" questions
- **Advanced**: Minimal explanation, jump to challenging applications, discuss tradeoffs and nuances
- **Adaptive**: Start where they claim to be, adjust based on how they actually respond
